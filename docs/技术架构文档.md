# 职路导航 — 技术架构文档

## 一、整体架构

职路导航采用**纯前端单文件架构**，无后端、无数据库、无构建步骤。所有数据（行业、专业、院校、题库）以内联 JSON 形式存储在 `index.html` 中。

```
┌─────────────────────────────────────────────┐
│                  index.html                  │
├──────────┬──────────┬──────────┬─────────────┤
│  HTML    │  CSS     │  JS      │  内联数据    │
│  页面结构│  Tailwind│  逻辑引擎│  DATA / 题库 │
└──────────┴──────────┴──────────┴─────────────┘
                    │
                    ▼
              localStorage（用户进度）
```

## 二、前端分层（index.html 内逻辑分区）

| 逻辑块 | 职责 | 关键函数 |
|---|---|---|
| `<script id="data">` | 静态数据：行业、专业、院校、题库、省考、简历模板 | `DATA.*`, `ZHILU_QUESTIONS` |
| `<script id="core">` | 路由、渲染、事件委托、localStorage 封装 | `route()`, `renderIndustries()`, `bindEvents()` |
| `<script id="quiz">` | 测评评分引擎、进度保存、退出/上一题 | `computeDimScores()`, `computeBaseScores()`, `renderResult()` |
| `<script id="kaoyan">` | 考研专业详情渲染 + 院校匹配算法 | `renderKaoyan()`, `runSchoolMatch()` |
| `<script id="job">` | 就业专业渲染 + 简历模板生成/下载 | `renderJob()`, `resumeTemplateHTML()` |
| `<script id="gong">` | 考公数据渲染 | `renderGong()` |
| `<script id="app">` | 初始化、事件绑定 | `init()` |

## 三、职业测评评分模型

### 3.1 维度构成

- **霍兰德 RIASEC**（6 型 × 4 题 = 24 题）：现实型 R / 研究型 I / 艺术型 A / 社会型 S / 企业型 E / 常规型 C
- **大五人格**（5 维 × 2 题 = 10 题）：开放性、尽责性、外向性、宜人性、情绪稳定（含反向计分）
- **职业情境**（8 题）：风险容忍 3 / 延迟满足 2 / 成就动机 3

### 3.2 评分流程

```
原始作答 → 反向题反转（6 - raw）→ 各维度均分（1-5）
    → 按赛道权重映射 → 四赛道适配度百分比
    → 取最高赛道为主推荐
```

### 3.3 赛道权重（基于职业心理学文献）

| 赛道 | 主要维度 |
|---|---|
| 考研 | 研究型 I、尽责性、延迟满足 |
| 考公 | 常规型 C、尽责性、情绪稳定 |
| 就业 | 企业型 E、外向性、成就动机 |
| 创业 | 企业型 E、风险容忍、成就动机 |

## 四、院校匹配算法

### 4.1 用户竞争力分（0-100）

```
综合竞争力 = 绩点分 × W1 + 英语分 × W2 + 预估分 × W3

其中：
  - 未填预估分时：W = [0.55, 0.25, 0.20]
  - 已填预估分时：W = [0.30, 0.15, 0.55]
```

- 绩点分：前 5%→95，前 10%→90，前 20%→82，前 30%→72，前 40%→62…
- 英语分：六级500+→90，六级→75，四级→55
- 预估分：≥400→95，380→88，360→78，340→68…

### 4.2 院校难度分（0-100）

```
难度分 = 层次分 + 热度分 + 自划线分 + 保护一志愿调整 + 复试线折算分

  - 层次分：985→22，211→10，双非→0
  - 热度分：★→0, ★★→3, ★★★→7, ★★★★→13, ★★★★★→18
  - 自划线：34 所自划线 +6
  - 保护一志愿：-4
  - 复试线折算：(中值 - 280) / 2.5
```

### 4.3 冲稳保分档

```
差值 = 院校难度分 - 用户竞争力分

  差值 ∈ [6, 16]   →  冲刺
  差值 ∈ [-4, 6)   →  稳妥
  差值 ∈ [-16, -4) →  保底
```

每档保证至少 3 所，不足时从相邻档位补充。

## 六、可演进方向

- **Level 1 前端模块化**：拆分为 `src/data/`、`src/modules/`、`src/components/`，引入 Vite 构建
- **Level 2 全栈化**：NestJS + Prisma，数据下沉数据库，支持多用户测评结果存储与院校库后台维护
- **数据扩展**：院校库从 84 所扩展到全量招生单位，引入专业维度难度差异
